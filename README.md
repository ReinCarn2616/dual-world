# 光影之间 · dual-world

一个 2D 双世界解谜平台跳跃游戏。同一张地图存在**光**与**暗**两个世界，起点与终点完全相同，但路线完全不同；玩家可以在任意时刻（奔跑中、跳跃中、静止时）瞬间切换世界。

**任何一个世界都无法单独通关**——这是本作的立身之本，也是每一关都经过书面推理 + 机器搜索双向验证的硬指标。

- 纯静态网页：原生 JavaScript（ES Modules），**零依赖、零构建步骤**，直接丢进 GitHub Pages 就能玩
- **11 关**：8 关教学 + 3 关进阶（地图比画面大，**摄像机跟随**，类似马里奥的滚动）
- 双世界叠影渲染（可选）、程序合成音效（不引入任何音频文件）
- 全程按**固定物理步长 1/120 s** 推进，60 Hz 与 144 Hz 显示器上的跳跃高度完全一致

## 快速开始

**Windows**：双击项目根目录的 [`start-game.bat`](start-game.bat)。
**macOS / Linux**：`./start-game.sh`。

它会找到 Node.js（先查 `PATH`，再查常见安装位置，最后兜底找 DSH 自带的运行时），起本地静态服务器，并自动打开浏览器；端口被占用会自动往后找 5174、5175……。**没有 Node.js 也没关系**：脚本会退回 Python 版服务器（[`tools/dev-server.py`](tools/dev-server.py)，同样零依赖）。

手动启动：

```bash
node tools/dev-server.mjs --open     # --open 会自动打开浏览器
python tools/dev-server.py --open    # 没有 Node 时的备选
```

> ES Modules 无法通过 `file://` 协议工作（CORS 限制），所以本地需要一个静态服务器。
> 两个服务器都只用系统自带的运行时，**不需要 npm install / pip install 任何东西**（Node ≥ 18 或 Python ≥ 3.7）。

> ⚠️ `start-game.bat` **必须保持纯 ASCII**：cmd.exe 按 OEM 代码页解析 `.bat`，文件里出现 UTF-8 中文会被拆坏、甚至当成命令执行（踩过这个坑）。中文提示一律由 Node/Python 服务器打印。冒烟测试里有一条断言专门守着这一点。

调试入口：

| 用法 | 作用 |
| --- | --- |
| `index.html?lvl=5` | 直接从第 5 关开始（跳过主界面） |
| `index.html?dev=1` | 显示开发提示（本地访问时默认开启） |
| `,` / `.` | 上一关 / 下一关 |
| `0` | 单世界调试开关：关闭 → 强制暗世界 → 强制光世界（用来人工核验"单世界无解"） |
| `H` | 看本关的标准解法演示（暂停菜单里也有按钮） |

## 界面结构

主界面按功能分成四个页签，键盘（`←` `→` 切页签、`↑` `↓` 换按钮、`回车` 确认）与鼠标都能操作：

| 页签 | 内容 |
| --- | --- |
| **开始游戏** | 开始按钮、已通关进度、三行玩法说明 |
| **选择关卡** | 按关卡分组显示（**教学关** 8 关 + **进阶关** 3 关），每关一张卡片，点一下直接进关 |
| **设置** | 声音（音效开关）、按键（6 个动作的当前绑定 + 进入按键设置子页 + 恢复默认）、成绩（清空成绩，二次确认）、显示（**叠影开关**、画布缩放倍率、逻辑分辨率、开发模式下的单世界调试开关） |
| **操作说明** | 按键表（全部由当前绑定动态生成）、核心机制三条、其他（`H` 看解法、计时口径） |

- **主界面不显示成绩**：通关进度只显示"已通关 N / M 关"，每关的最佳成绩放在该关的结算界面里看。
- **解法演示只在游戏内**：暂停菜单（`Esc`）里可以看本关标准解法，主界面不放这个按钮。
- 游戏内的 **暂停菜单** 同样是分区结构：继续 / 关卡（看解法、选关）/ 设置（按键、音效）/ 其他（返回主界面）。
- 文字全部在 DOM 里，canvas 只画游戏画面（§12.5 E1）。

### 关卡分组与"再加关卡"

关卡按组组织（`src/levels.js` 的 `LEVEL_GROUPS` + 每关的 `group` 字段）：

- **教学关**（8 关，20×12，画面正好装下整张地图）：把核心机制逐个教一遍。
- **进阶关**（3 关，地图大于画面，带解谜性质 —— 每关都专门打破一条教学关养成的直觉）：
- `三层折返`（56×20）：地图 20 行高、视野只有 12 行，终点在出生点上方 12 行、开局完全看不见；三层楼 + 两条竖井 + 一条假竖井，每层走廊地面各有一段 4 格宽熔岩且分属两个世界（跳不过去 → 必须换世界）；走廊上半部铺满交错小砖（两个世界错开，大半跳不到）。路线形状：右 → 左上 → 左 → 左上 → 左。
  - `反路`（44×16）：地面往右**全是通的**、看着像主路，走到头却是死墙；真正的入口是半路那个 2 格台阶，从墙顶跨过去才是终点。
  - `窄廊`（36×14）：一条净高 2 格的矮走廊（进去就跳不起来），**入口只有暗世界通、廊里的地面却要换着走** —— 暗世界两格熔岩、光世界另外两格，位置正好错开。

> **摄像机（进阶关）**：画面固定 640×384，地图更大时摄像机会跟随玩家 —— 水平方向带一点朝向预见与指数平滑，
> 竖直方向**只在落地时更新目标**，所以跳跃不会让画面上下抖动；地图不比画面大时（教学关）摄像机恒为 (0,0)，
> 行为与没有摄像机时完全一致。视差背景按摄像机位置平铺，任何偏移都不会露边。

加一关只需要在 `LEVELS` 里加一个对象（ASCII 网格 + `group` 字段），然后：

```bash
node tools/verify-levels.mjs --level 12        # 校验 + 单世界无解搜索
node tools/run-solutions.mjs --level 12 --verbose  # 逐段回放你写的解法磁带，定位哪一段跑偏
```

新分组会自动出现在选关页里；如果只想加进已有分组，`group` 写同一个 id 即可。

> 音频解锁（§9 的"首次用户手势"）由任意按键或任意点击触发，不再要求"按任意键开始游戏"。

## 操作（默认键位，全部可改）

| 操作 | 主键 | 备用键 |
| --- | --- | --- |
| 左移 | `A` | `←` |
| 右移 | `D` | `→` |
| 跳跃（可变高度） | `空格` | `W` / `↑` |
| **切换世界** | `J` | `Shift` |
| 重开本关 | `R` | — |
| 暂停 | `Esc` | `P` |

- 暂停菜单 → **按键设置**：6 个动作全部可重绑，每个动作支持多个槽位（改键是"增加一个键"而不是"替换掉一个键"），带冲突检测与持久化。
- 所有面向玩家的按键提示都由唯一一个 `keyLabel(actionId)` 动态生成（`src/settings.js`），**没有任何一处硬编码按键名**——把切换键改成 `K`，第 1 关的提示会同步变成"按 K 切换世界"。
- 输入一律使用 `event.code`，**绝不使用 `event.key`**：中文输入法下 `event.key` 可能是 `"Process"` 或全角字符，会导致跳跃直接失灵。

## 部署到 GitHub Pages

1. 仓库设为 **Public**，把整个目录推上去（`index.html` 在仓库根目录）。
2. `Settings → Pages → Source: Deploy from a branch → main / (root)`。
3. 等 1–2 分钟，访问 `https://<用户名>.github.io/<仓库名>/`。

工程上已经处理好的坑：

- 所有资源路径都是相对路径（`./src/main.js`、`./assets/...`），没有一处以 `/` 开头。
- 仓库根目录有 `.nojekyll`，避免 Jekyll 吞掉以下划线开头的文件/目录。
- 所有 `import` 路径与实际文件名大小写逐字符一致（Pages 跑在 Linux 上，`Player.js` ≠ `player.js`）。
- 没有任何后端、没有任何网络请求、没有运行时依赖（ComfyUI 只是离线出图工具，见下文）。

## 核心机制：切换保留位置与速度

```
按下切换键 → 目标世界 = 另一个世界
    在目标世界里，用玩家**完整的 AABB**（位置与尺寸完全不变）做一次碰撞检测
      与实心砖相交 → 切换失败：闪红 + 低频音效 + 震动，玩家留在原世界，
                     位置、速度、状态完全不变（失败零代价，无冷却）
      全空        → 切换成功：worldIndex 改变，
                     位置 (x, y) 与速度矢量 (vx, vy) 原样保留
```

- 速度矢量原样保留（S2）是"跳跃抛物线在空中被接续"的物理基础，也是"必须在上升段切换"这类谜题成立的前提。
- 切换成功意味着目标位置全空（S3），所以**切换后不可能卡墙**（S7），不需要任何"温柔挤出"逻辑。
- 目标世界脚下没地是**合法且高频使用**的谜题手段（"踩空救命"，S6）。
- 主循环里每个固定步的顺序严格是：采样输入 → 切换判定 → 水平加速 → 重力/垂直 → 分轴 AABB（先 X 后 Y） → 危险瓦片 → 越界 → 终点 → **计时累加（必须最后）**。顺序写错不会报错，只会让成绩恒定差 1/120 s。

## 关卡设计的硬性约束

物理量全部以「格」为单位（瓦片 32 px 只影响渲染）。`tools/verify-levels.mjs` 用真实物理实测出的包络：

| 量 | 文档推导值 | 实测值 |
| --- | --- | --- |
| 最大跳跃高度 | 2.33 格 | **2.39 格** |
| 全力跳跃水平距离 | 3.67 格 | **3.76 格** |
| 最大水平速度 | 5.5 格/s | 5.50 格/s |
| 滞空时间 | 0.67 s | 0.67 s |

由此得到三条设计判据（11 关全部遵守）：

1. **跳不过去的坑，宽度 ≥ 5 格**：坑宽 5 格时，从坑沿起跳到对岸需要约 4.25 格的水平位移 > 实测上限 3.76 格。坑宽 4 格（需 3.25 格）是能过去的。
2. **跳不过去的墙，高度 ≥ 4 格**：实测最大跳高 2.39 格。
3. **需要跳上去的台地，高度 ≤ 2 格**：进阶关里的攀爬段落全部是 2 格一阶。

## 验证与自测

四套脚本构成了"不需要人肉点击"的自动化验证：

```bash
node tools/verify-levels.mjs        # §6.2 校验 + A1 解法回放 + A2 单世界无解穷尽搜索（约 1–2 分钟）
node tools/verify-levels.mjs --single-only   # 只做校验与解法回放（1 s 内）
node tools/verify-levels.mjs --dual-search   # 额外跑一次启发式双世界搜索（参考用）
node tools/run-solutions.mjs        # 只回放 11 关的标准解法
node tools/run-solutions.mjs --level 11 --verbose   # 逐段打印位置/速度/世界，写磁带时用
node tools/smoke-test.mjs           # DOM 打桩跑完整启动/输入/渲染/摄像机/演示流程，150 项断言
python tools/gen-assets.py          # 重新生成全部 PNG 与预览图
```

`tools/verify-levels.mjs` 的搜索用的是 `src/sim.js`——与游戏**同一份物理**。搜索到任意一条通关路径都意味着"真的存在这样一串按键"；反过来，穷尽搜索证明"只在光世界"或"只在暗世界"根本走不到终点（§12.1 A2）。**11 关 × 2 个世界的 22 次搜索全部穷尽**且都没有路线（教学关用 1/4 格量化，进阶关地图大、改用 1/2 格量化并放宽状态上限）；每一关的书面推理见 [`doc/关卡验证.md`](doc/关卡验证.md)，机器结果见 `verify-report.txt`。

`tools/smoke-test.mjs` 覆盖：所有模块可导入、**manifest 声明的尺寸与真实 PNG 一致且每一帧都有像素**（PNG 解码后逐帧数不透明像素 —— 这条检查是为了一个真实踩过的坑：生成角色精灵表时只有第 0 帧有像素，表现是角色"一闪一闪"、跑起来直接消失）、素材整体缺失时的降级（E2）、主界面的功能分区与页签切换、键盘事件端到端（移动/跳跃/切换/暂停/R 重开/输入模块的松键）、暂停不涨计时（D1）、损坏存档逐字段回退（E7/D4）、11 关 × 两世界渲染零 error、绘制坐标合理、**摄像机（小地图不动 / 大地图横竖跟随且不越界）**、以及 **11 关标准解法演示在游戏运行时里逐关通关**。

## 美术资源与 ComfyUI

素材有三个来源，**优先级从低到高**，同名覆盖：

| 优先级 | 来源 | 产物 |
| --- | --- | --- |
| 1（兜底） | `src/procedural.js` 程序化绘制 | 代码画的贴图，永远可用，素材全丢也不白屏 |
| 2 | `tools/gen-assets.py` 生成的 PNG | `assets/` 下的正式贴图 |
| 3 | ComfyUI 离线出图（经后处理） | 覆盖同名 PNG，零代码改动 |

启动时读 `assets/manifest.json`，逐项加载；任何一项失败 / 尺寸不符 / 解析异常都会回退到程序化占位图并在控制台 `warn`，**不弹窗、不阻塞、不白屏**。所有帧偏移、动画帧序、播放速率都从 manifest 读取，渲染代码里没有硬编码的像素数字。

ComfyUI **只能离线出图**，绝不是运行时依赖（Pages 是 `https`，请求 `http://127.0.0.1:8188` 会被混合内容策略直接拦截）：

```bash
# 大图切成 4×4 格 → 每格最近邻下采样到 32×32 → 量化到该世界 5 色 → 无缝检查
python tools/prep-assets.py sheet comfyui_output.png --out assets/tiles/tileset-light.png \
    --grid 4x4 --world light --check-seam

# 视差远景：裁成 5:3 后缩放到 960×576
python tools/prep-assets.py bg keyvisual.png --out assets/bg/bg-light.png --world light
```

分工建议（§7.7.2）：**背景与插画交给 ComfyUI，瓦片与角色交给程序生成或手绘**。SD 类模型无法保证 32×32 无缝与帧间造型一致，硬啃通常比手画还慢。

## 已知限制

- **移动端只有显示，没有触屏操作**（§14 Q3 已确认）：手机上打开能正常居中显示、不崩，但键盘是唯一输入方式。
- 教学关第 3–8 关的最少切换次数低于文档 §6.3 的建议值（文档把它列为教学曲线的**建议**，不是验收项；§14 的已确认决策也已经删掉切换次数统计）。每关实际的最少切换次数与用时见 `doc/关卡验证.md`。
- 进阶关的地图比画面大，所以"看不见的部分"需要靠记忆或**打开叠影**（设置 → 显示）来判断 —— 默认关闭叠影时，这三关会明显更难。
- 关卡里"跳不过去的墙"一律做成 4 格高（符合 §4.2），但文档 §6.4 描述的 L1 暗世界墙只有 4 格 —— 本项目完全沿用文档的 L1 数据。

## 部署到 GitHub Pages

这是一个**纯静态、零构建**的项目（ES Modules + 相对路径 + `.nojekyll`），可以直接由 GitHub Pages 托管。

线上地址：<https://ReinCarn.github.io/dual-world/>

首次部署：

1. 在 GitHub 上新建一个 **public** 仓库 `dual-world`（不要勾选 README / .gitignore / license）。
2. 本地推送：
   ```bash
   git remote add origin https://github.com/ReinCarn/dual-world.git
   git push -u origin main
   ```
   （推送时 Git Credential Manager 会弹出一次 GitHub 登录窗口，凭据只留在本机。）
3. 仓库页 → Settings → Pages → Source 选 **Deploy from a branch** → Branch 选 `main`、目录选 `/ (root)` → Save。
4. 等 1 分钟左右访问上面的线上地址。

以后更新只需 `git add -A && git commit -m "..." && git push`，Pages 会自动重建。

> 注意：仓库保持在 **public** —— 免费账号只有公开仓库才能启用 Pages。
